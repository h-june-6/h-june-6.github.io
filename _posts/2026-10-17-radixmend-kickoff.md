> 앞으로 16주 동안 진행할 프로젝트 RadixMend를 소개하는 글이다. SGLang의 radix tree KV 캐시에서 생기는 비트플립을 attention 커널이 KV를 읽는 순간 고치는 소프트웨어 대응책을 만든다.

## 한 줄 요약

토큰·KV 헤드 벡터(256바이트)마다 15비트짜리 오류 정정 코드를 붙인다. 1비트 오류는 재계산 없이 읽는 순간 교정하고 메모리까지 복원한다. 2비트 오류는 탐지해서 재계산한다. 메모리 비용은 KV 대비 약 0.8%다.

## 왜 이 문제인가

### 공유하면 같이 망가진다

LLM 서빙 엔진 SGLang은 KV 캐시를 radix tree로 관리한다(RadixAttention). 시스템 프롬프트나 few-shot 예시처럼 여러 요청이 같은 prefix로 시작하면 그 prefix의 KV는 물리적으로 **한 세트만** 둔다. 덕분에 메모리와 계산을 크게 아낀다.

뒤집어 말하면, 그 한 벌에 비트 하나가 뒤집히면 그 prefix를 쓰는 모든 요청과 그 아래 자식 노드로 번진다. 루트 가까운 노드는 거의 모든 요청이 읽는다. 게다가 SGLang의 스케줄러(LPM)는 캐시된 노드를 타는 요청을 먼저 처리하기 때문에 공유 노드는 더 자주 읽힌다.

### 비트플립은 실제로 일어나고, 눈에 잘 띄지 않는다

- vLLM의 prefix caching을 대상으로 한 선행 연구(Yamamoto & Matsuura, 2026)는 공유 KV 블록의 value 텐서에 비트 하나를 뒤집어 봤다. BF16의 16개 비트 위치 중 13개에서 출력이 **문법적으로 자연스러우면서 원래와 다르게** 바뀌었다. 정답을 모르면 오염된 줄도 모른다는 뜻이다. 가수부 최하위 비트 하나만 뒤집어도 시행의 64%에서 적어도 한 요청의 출력이 바뀌었다(Qwen3-8B).
- 피해는 시간이 지나도 줄지 않았다. 오염된 블록이 캐시에 남아 있는 동안 이후 요청이 계속 영향을 받아 피해 요청 수가 요청 수에 비례해 늘었다.
- 하드웨어 공격도 실증됐다. GDDR6를 쓰는 RTX A6000에서 Rowhammer 비트플립이 보고됐고(GPUHammer) KV 캐시의 특정 좌표를 노리는 공격(CacheTrap)과 GPU 페이지 테이블을 조작해 권한을 올리는 공격(GDDRHammer, GeForge)도 나왔다. 한 영역에서 여러 비트가 뒤집힐 수 있다는 것도 보여 줬다.
- 그런데 GDDR 기반 GPU는 하드웨어 ECC가 보통 **꺼져 있다.**

### radix tree에서만 생기는 문제 두 가지

선행 연구는 value 텐서만 봤다. radix tree 구조에서는 문제가 두 개 더 생긴다.

**파생 오염.** 부모 노드 P의 레이어 ℓ가 오염된 상태에서 그 아래 자식 C가 prefill되면 C의 레이어 ℓ+1 이상 KV는 오염된 P를 보고 계산된다. 나중에 P를 고쳐도 C는 틀린 채로 남는다. C의 체크섬은 C 자신의 (틀린) 값으로 계산되어 앞뒤가 맞기 때문에 데이터 체크섬으로는 잡을 수 없다.

**인덱스 오염.** 트리 노드는 호스트 메모리의 Python 객체지만 각 노드가 가리키는 KV 슬롯 번호 목록과 요청별 슬롯 번호 표는 GPU 메모리의 텐서다. 슬롯 번호의 상위 비트가 뒤집히면 풀 밖을 읽어 엔진이 죽는다. 하위 비트가 뒤집히면 다른 요청의 KV를 읽어 요청끼리 데이터가 섞인다.

## 기존 방법으로는 왜 부족한가

| 기법 | 대상 | 한계 |
|---|---|---|
| hit 시점 해시 (선행 연구) | vLLM 공유 prefix 블록 | 검증과 사용 사이의 시간 창(TOCTOU)에서 생기는 파생 오염을 못 막음. 탐지만 하고 고치지 못함 |
| GPU 하드웨어 ECC | DRAM 전체 | A6000 기준 메모리 6.25% 감소, 대역폭 최대 12% 저하. GDDR에서는 기본으로 꺼짐 |
| ABFT 계열 | attention 연산 | 연산 중 오류가 대상. 캐시에 보관 중인 오류는 못 봄 |
| SAVE, DNN 소프트웨어 ECC | 모델 가중치 | 런타임에 생기고 공유되는 KV는 대상 밖 |
| SGLang PD 전송 체크섬 | PD 분리의 KV 전송 | 전송 직후 1회 검증, 탐지 전용, 기본값 꺼짐 |

기존 기법은 KV 오염을 **탐지만** 하거나, 연산 오류나 가중치를 대상으로 하거나, radix tree의 prefix 공유와 맞지 않는다.

## 핵심 아이디어: KV의 접근 패턴을 이용한다

KV 캐시는 일반 메모리와 쓰이는 방식이 다르다. 이걸 이용하면 하드웨어 ECC보다 훨씬 싸게 교정까지 할 수 있다.

1. **한 번 쓰고 읽기만 한다.** 토큰의 KV는 계산될 때 한 번 저장되고 슬롯이 해제될 때까지 안 바뀐다. 쓸 때 코드를 한 번 만들면 되고 read-modify-write 비용이 없다.
2. **항상 벡터 통째로 읽는다.** attention 커널은 토큰·KV 헤드마다 head\_dim 전체를 한 번에 읽는다. 그래서 코드 블록을 2048비트로 크게 잡을 수 있고 체크 비트 15개로 SECDED가 된다. 하드웨어 ECC(6.25%)의 약 8분의 1이다.
3. **KV를 읽는 곳은 attention 커널뿐이다.** decode와 extend 두 커널에서 검증하면 모든 소비가 검증을 거친다.

hit 시점에 한 번 검사하는 대신 **읽는 순간마다** 검사한다. 무결성을 구간마다가 아니라 끝에서 끝까지(end-to-end) 보장하는 셈이다.

## 시스템 설계: 모듈 네 개

### 모듈 A: 읽기 시점 자가 치유

- 벡터마다 15비트 체크워드(P, 원소 라벨 XOR, 비트 라벨 XOR, 전체 패리티)를 붙인다. KV 저장 커널에 인코딩을 합쳐서 저장과 인코딩 사이에 보호받지 않는 구간을 없앤다.
- decode/extend attention 커널이 K/V 타일을 읽은 직후 신드롬을 계산한다. 1비트 오류면 레지스터에서 바로 고쳐 attention 계산에 쓴다.
- 메모리는 커널 안에서 고치지 않고 오류 로그에 위치를 남긴다. 별도 scrub 커널이 재검증한 뒤 메모리에 쓴다. 같은 벡터를 여러 CTA가 동시에 읽는 경우의 중복 쓰기와, 3비트 이상 오류의 오교정 값이 메모리에 남는 것을 막기 위해서다.
- 자주 안 읽히는 노드는 유휴 시간에 순회하며 검사한다(백그라운드 scrubbing). 1비트 오류가 쌓여 2비트가 되기 전에 고치려는 것이다.
- 데이터 비트의 라벨은 키로 섞은 비밀 순열이다. 3비트 이상을 뒤집는 공격자가 원하는 오교정을 고르지 못하게 한다.

### 모듈 B: 자가 교정 인덱스

GPU에 있는 인덱스 텐서(req\_to\_token, node.value, 빈 슬롯 목록, seq\_lens)의 **쓰지 않는 상위 비트**에 SECDED 코드를 넣는다. 추가 메모리는 없다. 디코드는 몇 군데 choke point(kv\_indices 생성 커널, 슬롯 할당·해제)에 모은다. 2비트 오류가 나면 트리 경로의 node.value와 요청의 req\_to\_token이 서로 같은 정보를 담고 있다는 점을 이용해 교차 복구한다.

### 모듈 C: 읽기 게이팅과 계보 기반 복구

- 모든 읽기가 검증을 거치므로 오염된 부모를 읽어 자식이 오염되는 파생 오염이 원천 차단된다.
- 2비트 이상이 탐지되면 요청 단위 오류 플래그를 다음 토큰 복사에 실어 스케줄러로 보낸다. 그 스텝의 KV와 샘플 토큰은 버린다.
- 오염 노드를 poisoned로 표시하고 prefix 매칭을 그 앞에서 멈춘다. 그 노드를 쓰던 요청을 재등록하고 참조가 0이 되면 해제한다.
- 노드마다 born\_epoch, clean\_epoch를 기록해서 검증에 공백이 있었던 경우 오염 이후에 생긴 자손만 정밀하게 무효화한다.

### 모듈 D: 공유도 기반 차등 보호

가장 많이 공유되는 첫 레벨 노드(루트의 자식)와 attention sink 토큰의 K/V는 사본을 둔다. 2비트 오류가 나도 재계산이나 재등록 없이 바로 복원한다. 목적은 재계산 비용 절감이 아니라 **영향 범위 축소**다. 공유도 높은 노드가 poisoned되면 그걸 쓰는 요청 전부를 재등록해야 하기 때문이다.

## 위협 모델과 보호 범위

- 오류 원인: 무작위 soft error, 전송 오류, Rowhammer 같은 적대적 비트플립
- 공격자: 같은 GPU를 쓰는 다른 테넌트. KV에 직접 쓸 권한은 없고 비트플립만 유도할 수 있다.
- 보장: 한 벡터(256바이트) 안의 플립이 2개 이하일 때. 3개 이상은 비밀 라벨로 확률적으로만 완화한다.
- 범위 밖: KV를 계산하는 연산 자체의 오류. 트리 노드 객체는 ECC가 켜진 호스트 DRAM에 있다고 가정한다.

| 공격 대상 | 보호 없을 때 | RadixMend |
|---|---|---|
| K/V 벡터 1비트 | 조용히 출력이 바뀜 | 읽는 순간 교정, 메모리 복원 |
| K/V 벡터 2비트 | 조용히 출력이 바뀜 | 탐지 후 재계산 |
| 슬롯 인덱스 1비트 | 크래시 또는 요청 간 KV 혼입 | 교정 |
| 빈 슬롯 목록 | 이중 할당으로 KV 혼입 | 1비트 교정, 2비트 탐지 |
| 파생 오염 | 영구 오염 | 탐지 가능한 오류에 대해 원천 차단 |

## 어떻게 평가하나

소프트웨어 결함 주입 실험으로 네 가지 질문에 답한다. 주된 비교 대상은 선행 연구의 hit 시점 해시 기법을 SGLang에 옮긴 구현이다.

- **RQ1 특성 분석**: radix tree에서 피해가 어떻게 퍼지나. K 대 V, attention sink 위치, 인덱스 플립의 영향
- **RQ2 정확성·교정**: 정상 동작 유지, 비트 위치별 1비트 교정률(목표 100%), 체크비트 오류 시 데이터 보존, 2비트 탐지율
- **RQ3 비용**: TPOT, TTFT, 처리량, 메모리. decode와 extend 경로를 나눠서 측정(목표 TPOT 증가 3% 미만)
- **RQ4 봉쇄·복구**: 영향받은 요청 수, 파생 오염 노드 수, 재계산 복구 지연
